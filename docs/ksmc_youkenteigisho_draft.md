## 1. プロジェクト概要

### 1.1 名称
九産模型愛好会 公式サイト

### 1.2 目的
模型愛好会の活動紹介、部員による作品発信、新入生への入会案内を目的としたウェブサイトを構築する。

### 1.3 サイトの位置づけ
会員が自発的に作品を発信する**ギャラリーサイト**として運用する。単なる広報用の静的サイトではなく、会員個人の投稿とサークル公式の発信が混在するメディアとして位置づける。

### 2.2 ネットワーク・ドメイン
- FQDN想定：`ksmc.cs.kyusan-u.ac.jp`
- 上記ホスト名はサーバー払い出し申請上の登録にとどまり、学内外への実公開には別途「DNSサーバ登録申請書」の提出・承認が必要（**現時点で未完了**）
- ファイアウォール開放申請：別途提出・承認が必要（**現時点で未完了**）
- SSL証明書：別途申請が必要（**現時点で未完了**）
- 上記3件は本サイトの外部公開における最大のボトルネックであり、要件定義・開発と並行して最優先で手続きを進める

### 2.3 技術方針
- **CMS（WordPress等）およびフレームワーク（Laravel等）は使用しない**
- PHP（標準機能）＋MySQLによるスクラッチ実装とする
- 上記方針は、メモリ1GBという制約下での軽量動作、および部員が毎年入れ替わる中での引き継ぎのしやすさ（コードの平易さ）を重視した判断による

### 2.4 運用体制
- 顧問：システム上のロール・権限は付与しない。申請書記載の「私が顧問で確認をとります」は、サイト運用開始前（デプロイ前）に内容を一度確認するという運用上のニュアンスであり、投稿ごとの承認フロー等をシステムに実装するものではない
- 部員：日常運用（作品投稿、会員管理等）の主体
- 管理者アカウント：代替わりのたびに後任へ引き継ぐ

## 3. ステークホルダー

| 役割 | 内容 |
|---|---|
| 一般会員（部員） | 作品・記事の投稿（公開は即時、承認不要）、自分の投稿の編集・削除 |
| 広報担当 | 一般会員の権限に加え、サークル公式ブログへの投稿権限を持つ（管理者が付与） |
| 管理者 | 全会員・全投稿の管理（編集・削除権限を含む）、会員アカウントの発行（招待制）・ロック・削除、ロール付与、タグ管理、権限の引き継ぎ |
| 休止会員 | 退会・卒業した会員。ログインは可能。新規投稿とプロフィール編集は不可。パスワード再設定、既存の自分の投稿の編集・削除は可能（本人希望があれば削除） |
| 顧問 | システム上のロールは持たない。サイト公開前の内容確認のみを行う（運用上の位置づけであり機能要件の対象外） |
| 訪問者 | 学内外の一般閲覧者。会員登録なしで閲覧可能な範囲を想定 |

## 4. 機能要件

### 4.1 会員アカウント・作品投稿機能
| ID | 内容 |
|---|---|
| FR-01 | 会員登録は**管理者による招待制**とする。招待方法は**管理者が直接アカウント（ID・初期パスワード）を発行する形式**に確定（招待コード方式は採らない） |
| FR-02 | ログイン／ログアウト／パスワード再設定 |
| FR-03 | 会員プロフィール管理。**必須項目は表示名（名前）のみ**とし、その他の項目は会員の任意入力とする。**学年・専攻など学生としての個人情報は原則として公開欄を設けない**（サイト上に表示しない） |
| FR-04 | 作品投稿フォーム（画像＋タイトル＋本文＋タグ） |
| FR-05 | 下書き保存と公開の状態管理（下書き／公開の2状態。承認待ち状態は設けない） |
| FR-06 | 投稿の編集・削除は**投稿者本人が自分の投稿に対して行える**ほか、**管理者は全会員の投稿に対する編集・削除権限を持つ** |
| FR-07 | 会員が記事を公開する際、**管理者・顧問による承認は不要**とし、投稿操作をもって即時公開とする（顧問の確認はデプロイ前の一度きりの確認であり、投稿単位の承認フローではない。第2.4節参照） |
| FR-08 | アップロードファイルの制限（画像形式・サイズ）。**容量上限は投稿単位で設定する**（会員単位での総量上限は設けない）。具体的な数値（MB／投稿）は**要決定** |

### 4.2 管理者アカウントの引き継ぎ

会員の招待制（FR-01）、公式ブログ投稿権限（FR-14）、退会・卒業会員の扱い（FR-11）の決定を踏まえ、ロール構成を以下の4種類に整理する（顧問用のロールは設けない。第2.4節・第3章参照）。

| ロール | 権限概要 |
|---|---|
| 会員 | 作品記事の投稿・自分の投稿の編集削除。デフォルトのロール |
| 広報担当 | 会員の権限に加え、サークル公式ブログへの投稿権限を持つ。管理者が会員の中から付与する |
| 管理者 | 全会員・全投稿の管理、アカウントの発行／権限付与／ロック／削除、タグ管理、管理者権限の委譲 |
| 休止会員 | 退会・卒業した会員に付与。ログイン・パスワード再設定・自分の既存投稿の編集/削除は可能。新規投稿・プロフィール編集は不可 |

| ID | 内容 |
|---|---|
| FR-09 | ロールは「会員」「広報担当」「管理者」「休止会員」の4種類とする |
| FR-10 | 管理者権限の委譲機能（新管理者の指定、旧管理者の降格） |
| FR-11 | 退会・卒業した会員アカウントは**原則ロック処理（休止会員ロールへの変更）**とする。本人から削除の要望があった場合はアカウントを削除する。要望がない場合は休止会員ロールを割り振り、アカウントと投稿を残す。休止会員は**ログイン・パスワード再設定・自分の既存投稿の編集/削除は可能**とし、**新規投稿とプロフィール編集は不可**とする |
| FR-12 | 引き継ぎ手順書の整備（システム機能ではなく運用ドキュメントとして別途作成） |

### 4.3 記事種別（個人作品記事／サークル公式ブログ）
| ID | 内容 |
|---|---|
| FR-13 | 投稿を「個人の作品記事」と「サークル公式ブログ記事」に区分するデータ構造 |
| FR-14 | 公式ブログへの投稿権限は**「広報担当」の専用ロールを持つ会員に限定**する（一般会員・休止会員は投稿不可） |
| FR-15 | トップページ・一覧ページでの表示区分 |

### 4.4 タグによるカテゴライズ
| ID | 内容 |
|---|---|
| FR-16 | 投稿時のタグ付与は**新規タグの入力欄と既存タグの選択欄を併用する形式**とする（自由入力と選択式の両方を許可） |
| FR-17 | 管理者によるタグの統合・編集機能（表記ゆれ対策） |
| FR-18 | タグ別一覧ページ、複数タグでの絞り込み検索 |

### 4.5 アップロード画像へのロゴ挿入
| ID | 内容 |
|---|---|
| FR-19 | 画像アップロード時に、**投稿者自身がロゴの位置・サイズ・透過度等を調節できる入力フォーム**を提供し、投稿者の操作に基づいてロゴを合成する（自動一律合成ではなく投稿者の調整を伴う方式）。フォームの具体的な操作項目（プレビュー表示の要否など）は**要決定** |
| FR-20 | 処理タイミングは、投稿者がフォームで調整・確定した内容に基づき**投稿保存時に同期処理**する（FR-19の方式に伴い確定。非同期キューは不要） |
| FR-21 | 元画像（ロゴ合成前）を別途保存するかどうかは**要決定** |

## 5. 非機能要件

| ID | 内容 |
|---|---|
| NFR-01 | メモリ1GB・1vCPUの環境で安定動作すること（常駐プロセス数、MySQL同時接続数を抑えた設計とする） |
| NFR-02 | セキュリティ：SQLインジェクション・XSS・CSRF対策、アップロードファイルの拡張子偽装対策、初期発行パスワード（SSH等）の変更運用 |
| NFR-03 | 可用性：障害時の切り分け窓口（大学総合情報基盤センター）を運用ドキュメントに明記する |
| NFR-04 | 保守性：部員が毎年入れ替わる前提での平易なコード構成、最低限のコメント・引き継ぎ資料の整備 |
| NFR-05 | 容量管理：ディスク容量50GBを超えないよう、投稿単位の上限設定（FR-08）に加えアップロード総量を監視する仕組み |
| NFR-06 | バックアップ：**当面は手動でのローカルバックアップとする**（DB・画像データを定期的に管理者の手元にエクスポートする運用）。自動化・遠隔保管は将来の検討事項とする |

## 6. データ設計方針（概略）

詳細設計は別途行うが、要件レベルでは以下の大枠を想定する。

- 会員（users）：ID、表示名（必須）、その他プロフィール項目（任意入力・非公開扱い）、ロール（会員／広報担当／管理者／休止会員）
- 投稿（posts）：投稿種別（個人作品／公式ブログ）、タイトル、本文、画像パス、容量（投稿単位で上限管理）、公開状態（下書き／公開の2状態）、投稿者
- タグ（tags）・投稿とタグの中間テーブル
- 画像（images）：オリジナル画像、投稿者が調整したロゴ合成後画像のパス管理

## 11. 未確定事項・要確認事項一覧

### 11.1 確定済み事項

**v0.2にて決定**
- 会員登録の方式：管理者による招待制
- 投稿の公開前承認フローの要否：不要。会員の投稿操作をもって即時公開

- 投稿の編集・削除権限：投稿者本人（自分の投稿のみ）と管理者（全投稿）が保持

**v0.3にて決定**
- ディスク容量：50GBを実際値として採用
- 招待方式：管理者が直接アカウント（ID・初期パスワード）を発行する形式
- 会員プロフィール：必須項目は表示名のみ。学年・専攻等の個人情報は原則公開欄を設けない

- ロゴ合成：投稿者自身が位置・サイズ・透過度等を調節できる入力フォームを提供し、投稿保存時に同期処理で合成
- 退会・卒業会員：原則ロック処理（休止会員ロールへ変更）。本人希望があれば削除

- ホスティング申請：承認済み

**v0.4にて決定**

## 12. 受け入れ基準（案）

- 上記機能要件（FR-01〜FR-21）が本番相当環境（RHEL10.1／Apache／MySQL、CMS・フレームワーク不使用）で動作すること
- メモリ1GBの環境下で著しい遅延やプロセス落ちが発生しないこと
- 主要ブラウザおよびスマートフォンでの表示崩れがないこと
- ディスク容量50GBの上限に対してアップロード総量が制御されていること

## 13. 用語集

- **九産模型愛好会**：本サイトの運営主体である大学の模型サークル
- **ギャラリーサイト**：会員が作品（模型の写真・記事）を発信する場として運用するサイト形態
- **公式ブログ**：個人の作品記事とは別に、サークルとして発信する活動報告等の記事
