# 管理者引き継ぎ手順書（FR-12）

要件定義書FR-12に基づく運用ドキュメントです。システム機能ではなく、管理者交代時に人が行う作業の手順をまとめています。年度替わりなどで管理者が交代するたびに、このドキュメントに沿って作業してください。

対象読者：現管理者（引き継ぐ側）、新管理者（引き継がれる側）

## 1. 引き継ぎの流れ（全体像）

1. 新管理者になる人のアカウントを用意する（既存会員ならそのまま、未登録なら招待する）
2. サイト上で管理者権限を委譲する（本手順書の第3章）
3. サーバー・インフラ関連の情報を引き継ぐ（本手順書の第4章）
4. 旧管理者は権限が「会員」に変わったことを確認する
5. 新管理者は一通りの管理機能にログインできることを確認する

## 2. 事前準備

- 新管理者になる人が会員アカウントを持っていない場合は、先に `/account_create.php`（アカウント発行画面）から招待してください（FR-01）。
- 新管理者になる人のログインIDを控えておいてください。委譲操作で必要です。

## 3. サイト上での管理者権限の委譲（FR-10）

1. 現管理者でログインし、`/account_manage.php`（アカウント管理画面）を開く
2. 新管理者になる人のログインIDで検索する
3. 表示されたアカウント情報に間違いがないか確認する（表示名・ログインID）
4. 「管理者権限を委譲する」を押す
5. 確認画面で対象者を再確認し、「委譲を実行する」を押す
6. 実行すると、現管理者は自動的に「会員」ロールになり、新管理者が「管理者」になる

**注意**：この操作は取り消せません（もう一度委譲すれば戻すことは可能ですが、誤操作すると一時的に管理者不在になり得ます）。委譲前に、新管理者になる人のログインIDに誤りがないか必ず確認してください。

## 4. サーバー・インフラ関連の引き継ぎ

システム機能では管理できない情報のため、別途安全な方法（対面での口頭伝達など、テキストで残さない方法を推奨）で引き継いでください。

- サーバーのSSHログイン情報
- データベース（MySQL）の接続情報（`.env`ファイルの内容）
- 大学総合情報基盤センターへの申請時の管理者情報（申請書番号 SH202600035）
- ドメイン・DNS・SSL証明書関連の申請状況（要件定義書 第10章参照）
- ホスティングサーバーの管理画面・認証情報（あれば）

`.env`ファイルは本リポジトリの`.gitignore`対象であり、Gitには含まれません。サーバー上の`.env`ファイルの場所と内容を、新管理者が直接確認できるようにしてください。

## 5. バックアップの引き継ぎ（NFR-06）

現状バックアップは手動・ローカル運用です。以下を新管理者に引き継いでください。

- 直近のバックアップの保管場所
- バックアップの取得方法（DB・アップロード画像のエクスポート手順）
- 最後にバックアップを取得した日付

## 6. 退会・卒業した会員の扱い（FR-11）

管理者交代のタイミングは、退会・卒業した会員の整理を行う良い機会でもあります。

- 退会・卒業した会員は、本人から削除の希望がない限り `/account_manage.php` から「休止会員にする（ロック）」を実行してください。投稿はそのまま残ります。
- 本人から明確にアカウント削除の希望があった場合のみ「アカウントを削除する」を実行してください。**投稿・画像も含めて完全に削除され、取り消せません。**

## 7. 引き継ぎ後の確認事項

- [ ] 旧管理者：`/account_manage.php` にアクセスできない（会員ロールになっている）ことを確認した
- [ ] 新管理者：`/account_manage.php` にアクセスできることを確認した
- [ ] 新管理者：`/account_create.php` からアカウント発行ができることを確認した
- [ ] サーバー・DB・バックアップ関連の情報を受け取った
- [ ] 緊急時の相談先（顧問・大学総合情報基盤センターの窓口）を把握した
